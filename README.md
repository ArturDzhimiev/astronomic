# ASTRONOMIC — рецептурник (React)

Двуязычное (RU/ES) приложение рецептурника бара: заготовки, блюда, граммовки, поиск.
Первый модуль будущего сервиса — дальше сюда добавятся меню, себестоимость и закупки.

Стек: **React 19 + TypeScript + Vite**, роутинг — `react-router`, стили — CSS Modules
поверх дизайн-токенов, тесты — Vitest + Testing Library, линт — oxlint, формат — Prettier.

Оформление монохромное — белый лист, чёрная краска, тонкая строчная типографика
фирменного знака. Язык по умолчанию испанский (кухня работает на нём), выбор
запоминается в `localStorage`.

## Команды

```bash
npm install        # установка зависимостей
npm run dev        # дев-сервер (http://localhost:5173)
npm run build      # прод-сборка в dist/
npm run preview    # локальный просмотр прод-сборки
npm test           # юнит-тесты
npm run lint       # oxlint
npm run typecheck  # проверка типов
npm run format     # Prettier
```

## Структура

```
src/
├── app/                       # оболочка: layout, шапка, роутер
├── features/
│   └── recipes/               # модуль «Рецепты»
│       ├── api/               #   доступ к данным (сейчас статика, потом бэкенд)
│       ├── components/        #   карточка, таблица ингредиентов, легенда
│       ├── data/recipes.json  #   данные рецептов
│       ├── lib/               #   поиск и фильтры
│       ├── model/             #   типы домена
│       └── pages/             #   страницы списка и рецепта
├── i18n/                      # словари RU/ES и провайдер языка
├── shared/                    # переиспользуемое: ui-примитивы и утилиты
├── styles/                    # токены и глобальные стили
└── test/                      # setup для Vitest
```

Поиск (`features/recipes/lib/search.ts`) идёт по названиям и индексирует оба
языка сразу: блюдо можно спросить по-испански, а найти в русском интерфейсе.
Диакритика игнорируется — `jalapeno` находит `jalapeño`.

Заготовки внутри блюд кликабельны: из состава можно перейти на карточку заготовки.

## Данные

Источник истины — `src/features/recipes/data/recipes.json`. Ингредиенты хранятся
объектами с разобранным числовым количеством (`amount`) и единицей (`unit`) —
это основа для будущего расчёта себестоимости.

Там же лежат связи «блюдо → заготовка»: из состава блюда можно кликнуть
на заготовку и перейти на её карточку. Разрешено 50 упоминаний из 74 —
остальные заготовки (чимичурри, бешамель, сопе из синей кукурузы и др.)
в исходных данных отсутствуют и остаются обычным текстом. Появятся —
добавляются прямо в `recipes.json`.

Файл собран из первой HTML-версии рецептурника: она вместе со скриптом
конвертации лежала в корне репозитория и удалена за ненадобностью —
при необходимости обе найдутся в истории git, в коммите `7c478c8`.

Весь доступ к рецептам идёт через `features/recipes/api/recipesRepository.ts` —
когда появится бэкенд, меняется только он.

## Деплой

Пуш в `main` запускает `.github/workflows/deploy.yml`: линт → типы → тесты →
сборка → публикация на GitHub Pages.

`base` для Pages вычисляется автоматически в `vite.config.ts` из переменной
`GITHUB_REPOSITORY`, так что переименование репозитория ничего не ломает.
Для своего домена достаточно задать `VITE_BASE=/`.

Роутер — `createHashRouter`: GitHub Pages не умеет отдавать `index.html`
на произвольный путь, а с адресами вида `#/recipes/pan-brioche` прямые ссылки
и перезагрузка работают без серверных правил.
